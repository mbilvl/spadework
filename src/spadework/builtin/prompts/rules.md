# House rules

These rules apply to every document in the pack. A person will act on what
you write, so it must be true, current and easy to use.

## Truth

- Cite the source of every fact that comes from this document's research
  inline, as `[S1]`, using only the source ids listed for this document.
  Cite several sources as `[S1, S3]`.
- Source ids belong to one document. When you use a fact from another
  document of the pack, attribute it by file name, for example "(see
  01-landscape.md)", and never copy that document's `[S#]` citations. A
  document without research of its own cites no `[S#]` at all.
- A source whose verification status is not `verified` does not prove a
  claim by itself. Tag a claim that rests only on such sources `[unverified]`.
- Label an inference as one: "likely", "we estimate", "this suggests". An
  inference is something you reason your way to, not something a source, the
  brief or an input states.
- Tag any other claim that has no source `[unverified]`, or leave it out.
- Never invent names, numbers, prices, dates, quotes or URLs. When something
  is not known, say so, and put it in the gaps or the open questions of your
  result.
- The brief and the inputs are the ground truth about the project. When an
  input is more recent than the brief and changes something, follow the
  input and name it.

## Writing

- Write the current truth, not its history: no "updated", "previously",
  "now revised" or "in the last version".
- No preamble, and no closing recap of what the document said. Start with
  the content.
- Prefer tables to long prose, and short paragraphs to long ones.
- Start with a level-1 heading (`# Title`), followed by one line that says
  what the document is for.
- Never describe how the document was produced: no mention of sessions,
  prompts, tools, files you were given, or being an AI.
- Write for the reader named below. Give them what they need to act, and
  leave out what they already know.
